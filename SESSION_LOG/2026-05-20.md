# Session 2026-05-20 — Forge fitter built; Talking Hedz calibration partial

## Goal

Start the Forge: a Bark/ERB-weighted fitter that authors original 6-biquad
bodies, calibrated by remaking Talking Hedz behaviour the Clean Room way.

## Built

- `pyruntime/forge_fit.py` — Bark/ERB-weighted, phase-aware cascade fitter.
  Fits a target complex response with a 6-biquad cascade. Coefficient
  domain is d-space (the 5 minifloat-decode components per stage, bounded
  [0,1]) so an authored corner survives encode→u16→decode. Per-body
  perceptual profiles (vocal/sub/bright/broad). Forge pipeline — no
  Compiler imports.
- `tools/forge_hedz_calibration.py` — fits the 4 ROM-decoded corner
  responses, encodes, interpolates M50/Q50, nulls vs the X3 wet.
- `tools/forge_corner_fit.py` — fits each corner from its measured X3
  corner wet (exact-lag-aligned full-FFT transfer function H = Y/X).

## Results

- **Fitter works on clean targets.** −272 dB weighted response match;
  authored corners render post-encode at −183 to −230 dB vs the
  ROM-decoded reference.
- **Independent per-corner fits do not morph.** Each corner lands on a
  different valid 6-biquad factorisation; the u16-word morph lerp needs
  coherent stage identity. M50/Q50 from independently-fit corners nulled
  −0.69 dB.
- **Corner wets received** (`Downloads\hedz regions - m{0,1}q{0,1}.wav`):
  the 2 Q0 wets match the ROM corners bit-accurately (ROM kernel renders
  null −98.8 / −100.3 dB); the 2 Q100 wets match nothing (−0.2 dB across
  all 16 ROM-corner × wet pairings) — bad / non-static captures.
- **Measured-wet fit is unreliable.** Best: M0_Q0 = −40.3 dB render-vs-wet.
  M100_Q0 collapsed to −1 dB in the harness though −50 dB is reachable at
  the correct lag (3421) — the lag-refinement loop diverges.

## Bugs found and fixed

- `find_lag` is offset from the true wet/dry lag by the filter group delay
  (~8–12 samples). The TF needs a sample-exact lag — a 1-sample error
  rotates H by z^k and makes it unfittable. Added a deconvolution-onset +
  causality refinement (still ±1 fragile; see below).
- A coarse log grid cannot resolve the corners' Q≈160–600 resonances;
  switched the fit to the native FFT grid (decimated).

## Honest verdict

Talking Hedz is **not recreated**. The Forge fitter core is sound and
proven on clean targets. The measured-wet front-end (sample-exact lag +
low-variance TF estimate) is the bottleneck and is fragile. Morph
coherence (joint fit) is unsolved. The 2 Q100 captures are unusable.

## The lesson — locked

**Independent per-corner fitting is invalid for morph bodies.** A
morphing body is *one staged instrument with four coordinated corners*,
not four filters. Stage *i* must be the same actor in every corner; the
encoded morph lerps words stage-by-stage and is meaningless otherwise.
Authoring discipline: fit morphable **bodies**, not filters.

## Next

1. Stabilise the measurement: exact lag decoupled from the fit loop;
   low-variance TF (Welch-averaged), noise floor below −60 dB.
2. Joint coherent fit — 4 corners, shared stage identity — so the morph
   works. For the Talking Hedz fixture, add the X3 M50/Q50 wet as a 5th
   joint target.
3. Recapture the 2 Q100 corner wets static, or use ROM-decoded Q100
   responses as the reference.

# Session 2026-05-20 — Ghidra parameter-entry stress test

## Goal

One last Ghidra-side check before pivoting prompts: ignore the runtime
filter loop and inspect parameter-entry / packed-state writing logic.

## Findings

- `FUN_1802c02b0` and live update path `FUN_1802d1600` both follow the
  same state refresh chain: class-specific virtual writer -> `FUN_1802c3d40`
  packed morph/Q interpolation -> `FUN_1802c3600` decode to floats.
- `FUN_1802c3d40` remains a 4-corner u16 bilinear interpolator. No 8-corner
  cube or hidden trajectory store appeared in this path.
- `FUN_1802c3600` is decode/recombine: minifloat decode, c0/c2 recombine,
  and `c4 = this+0x2a8 * d4`; `FUN_1802c0150` initializes that scale to
  `4.0`.
- `FUN_1802c6590` is the MorphDesigner-style parameter compiler. It reads
  six stage records from descriptor bytes at `param_2 + 0x22`, applies type
  1/2/3 logic, writes corner banks at `param_3 + 0x2C0/0x2FC/0x338/0x374`,
  pads with `DAT_1806d7500`, and sets active stage count at `+0x420`.
- Type 3 has real hidden constraints: the split-code hack around `0xDB/0xDC`,
  high-frequency compression, class-dependent base tables, and a special c4
  branch. These are compiler constraints, not runtime cascade changes.
- MorphLP/MorphLPX/Morph2 writers (`FUN_1802c5d60`, `FUN_1802c5e40`,
  `FUN_1802c5f10`, `FUN_1802c6020`) also write the same four corner banks,
  using compact descriptor bytes plus static tables (`DAT_1806d73c0`,
  `DAT_1806d7480`, class-specific scale/base tables).

## Verdict

There is an original encoder/compiler in the firmware, but it is not a
generic "frequency Hz -> 14-bit Z-plane word" inverse fitter. It is a set of
class-specific descriptor compilers from small packed stage parameters into
the u16 corner banks. For Talking Hedz/P2K skins, the open question remains
whether the FilterP2k class copies a runtime-loaded bank table or compiles a
descriptor; the live object dump at `+0x2C0` is still the shortest truth step.

## Next

1. In Ghidra, identify the `FilterP2k` virtual writer adjacent to the vtable
   region around `0x1806d6150` and confirm whether it copies 240 bytes or
   compiles stage descriptors.
2. In Cheat Engine, dump the live Talking Hedz object `+0x2C0..+0x3B0` and
   compare with `tools/rom_words_compare.py`.

### Locked tonight

> **Words name the roles. Packed words play the roles. Four corners make the body.**

The architecture in 13 words.

- ARMAdillo = trajectory between corners (runtime, frozen, bit-accurate at
  −95 dB on Talking Hedz ROM). ARMA = per-corner extraction (authoring,
  what `forge_fit.py` already does). Don't conflate.
- Universal Forge stage vocabulary: Root / Body / Mouth / Scar / Edge / Rip.
  Same six labels for every body. Frequency band per stage differs per
  body. Earlier per-body label drafts superseded.
- Stages are fixed-role actors across all 4 corners. Stage *i* carries
  the same label in every corner; the actor's frequency may migrate
  inside its band (verified by the ROM stage-layout audit — stages 1
  and 5 of Talking Hedz cross in frequency along M).
- Labels are authoring-side metadata only. Runtime sees only packed u16
  + global boost. No role logic at runtime.
- df2 ships as 2 plugins: player (consumer, with sample import slot) +
  forge (mixer-channel capture-and-author). `pyruntime/` FastAPI is the
  internal engine behind the forge plugin, not a third plugin.
- −53 dB vs −95 dB gap is dominantly cartridge format precision floor
  (frozen format stores floats and re-packs at load). For destruction-
  machine bodies aimed at beat producers the floor is below where the
  bodies operate. Format stays frozen.

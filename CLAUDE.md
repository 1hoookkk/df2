# TRENCH

Loop: inspect → smallest change → run → show the evidence. Repeat. No plans,
no reports, no menus while the next move is obvious.

- Every number comes from a table, a measurement, or the toolchain. Hand-typed
  = stop.
- `FILTER_NOTEBOOK.md` = law. Read before touching filters; one home per fact;
  wrong lines get deleted, not amended.
- `trench-core` is the only engine/compiler/codec. Judge through packed bytes
  and the shipping chain, never design math.
- P2K/X3/ref = study only. No E-mu bytes ship. Provenance = how it was made.
- Start from the live worktree, not memory or a story. Grep for existing tools
  before writing any.
- Tyson's words verbatim = the spec. His correction = new ground truth,
  applied immediately, old conclusions dead.
- One change per verdict. A direction that fails twice = change the method.
- Prove one case end-to-end on the real surface (packed runtime, true scale,
  emitted bytes) before any batch, install, or claim. Ear decides character.
- Installs and roster changes are gated on his explicit go.
- Plots: fixed −60..+30 dB scale, dense packed-runtime evals, no autoranging.
- Nothing is "done" until the proof ran. Say what changed, what it shows,
  what's next. Terse.
